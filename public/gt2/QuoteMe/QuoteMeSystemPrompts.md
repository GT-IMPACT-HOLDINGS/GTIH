# QuoteMe System Prompts Reference

## Overview
This document catalogs all system prompts (narratives) used in QuoteMe for GT3 inference calls. Each prompt is documented with its context, full text, dynamic arguments, and expected output.

**Note:** All prompts use the role: "Sales Proposal Assistant for global B2B sales."

---

## Inference Call A: Generate Proposal Anatomy (PA)

### Context
- **Trigger:** Immediately after user submits Profile on Landing page (first-run onboarding)
- **Location:** `index.html` - Profile form submission handler
- **Function:** `buildPANarrative(profile)` in `inference-narratives.js`
- **GT3 Call:** `callGT3(narrative)` in `index.html` line ~582

### System Prompt Template
```text
ROLE: Sales Proposal & Quoting Assistant for global B2B.

OPERATING PRINCIPLES:
- Draft-first: write editable drafts; never "lock" decisions.
- Do not invent facts. If missing, use <<<TBD>>> and add to "Open Questions".
- Prefer internationally neutral wording (avoid country-specific legal/tax claims).
- Use ISO dates (YYYY-MM-DD). Avoid slang, hype, emojis.
- Match the language of NEW INPUT (or the dominant language of the opportunity).

PROFILE: {profileProse}

TASK:
Create a reusable Proposal Anatomy (PA) tailored to the profile, optimized for fast global quoting and professional engagements.

OUTPUT REQUIREMENTS:
Produce a section outline, in this exact order, with 1–3 sentences of recommended boilerplate micro-copy under each:

1) Opportunity Summary
2) Customer Context & Goals
3) Proposed Solution (What we provide)
4) Scope (Inclusions)
5) Out of Scope / Exclusions
6) Deliverables
7) Timeline & Milestones
8) Customer Responsibilities
9) Assumptions
10) Pricing & Packaging (structure only; no numbers unless given)
11) Commercial Terms (currency, payment terms, validity period, taxes note)
12) Compliance / Security / Legal Notes (neutral)
13) Implementation Plan / Workplan Snapshot
14) Next Steps
15) Appendix (optional)

RULES:
- Minimal placeholders; only where they truly help.
- Use <<<TBD>>> where profile lacks specifics (pricing model, regions, ICP).
- Match the language of PROFILE.
```

### Dynamic Arguments
- **`{profileProse}`** - Generated by `profileToProse(profile)` function:
  - Includes: Name, Role (if provided), Company Name, Industry/Segment, Geography, Product/Service Category
  - Optional: Company Description (if provided)
  - Format: "Name: {name}. Role: {roleTitle}. Company: {companyName}. Industry: {industrySegment}. Geography: {geography}. Product/Service: {productServiceCategory}. Company description: {companyDescription}."

### Expected Output
- A Proposal Anatomy document with:
  - **15 sections in exact order** (Opportunity Summary through Appendix)
  - Suggested micro-copy (1-3 sentences) under each section
  - Placeholders `<<<TBD>>>` where profile lacks specifics
  - **No invented pricing, dates, SLA, legal clauses, or compliance certifications**
  - Generic enough for global reuse but tuned to the profile
  - Fully editable by the user

### Storage
- Saved as global `pa.text` in `quoteme.v1.pa`
- Editable anytime from the PA page

## Inference Call B: Propose Opportunity Title

### Context
- **Trigger:** When Opportunity title field is empty/whitespace, after user provides NEW INPUT (uploaded document or entered text)
- **Location:** `opportunity.html` - NEW INPUT upload handler and Status approval handler
- **Function:** `buildTitleNarrative(profile, newInput)` in `inference-narratives.js`
- **GT3 Call:** `callGT3(narrative)` in `opportunity.html` lines ~564, ~1075

### System Prompt Template
```text
ROLE: Sales Proposal Assistant for global B2B sales.

PROFILE: {profileProse}

NEW INPUT: {newInput}

OUTPUT REQUIREMENTS:
- 8–12 words maximum.
- No emojis.
- Include customer name if present in NEW INPUT.
- Include product/solution keyword if present.
- Avoid internal jargon.
- Avoid sensitive personal data.
- Match the language of NEW INPUT.

Output only the title text, nothing else.
```

### Dynamic Arguments
- **`{profileProse}`** - Generated by `profileToProse(profile)` (same format as Call A)
- **`{newInput}`** - The newly uploaded/entered document text or narrative:
  - Extracted from uploaded file (.txt, .docx) or pasted text
  - Normalized and cleaned (per `text-extraction.js`)
  - Full text content (up to reasonable length limits)

### Expected Output
- A single-line title string (4-9 words, shorter = better)
- No emojis, no quotes, no ending period
- Includes customer name if present
- Includes product/solution keyword if present
- Includes region/country if present (e.g., "Germany", "EMEA")
- Matches the language of NEW INPUT
- **Client-side rule:** Applied only if title field is empty/whitespace

### Storage
- Saved to `opportunity.title` in `quoteme.v1.opportunities[]`
- Fully editable by user

## Inference Call C1: Generate/Update Workplan

### Context
- **Trigger 1 (Status Approval):** User manually edits Status textarea, then approves Status (via glyph toggle). If Workplan is empty, triggers Workplan generation.
- **Trigger 2 (NEW INPUT):** User uploads a new document for an Opportunity. Triggers Workplan generation from Profile + previous approved Workplan/Status + NEW INPUT.
- **Location:** `opportunity.html` - Status approval handler and NEW INPUT upload handler
- **Function:** `buildWorkplanNarrative(profile, previousWorkplan, previousStatus, newInput)` in `inference-narratives.js`
- **GT3 Call:** `callGT3(narrative)` in `opportunity.html` lines ~445 (parallel with Status), ~534 (Status approval)

### System Prompt Template
```text
ROLE: Sales Proposal Assistant for global B2B sales.

PROFILE: {profileProse}

PREVIOUS APPROVED WORKPLAN: {previousWorkplan}

PREVIOUS APPROVED STATUS: {previousStatus}

NEW INPUT: {newInput}

OUTPUT REQUIREMENTS:
Output only the updated Workplan.

Maximize stability:
- Do not rewrite existing steps unless new input requires it.
- Prefer appending or minimally editing.
- Make steps actionable and sequenced.
- Insert placeholders <<<TBD>>> where needed.
- Match language of NEW INPUT.
```

### Dynamic Arguments
- **`{profileProse}`** - Generated by `profileToProse(profile)` (same format as Call A)
- **`{previousWorkplan}`** - Previous approved Workplan text:
  - From `opportunity.workplanText` if exists and approved
  - Default: "No previous workplan exists." if empty or not approved
- **`{previousStatus}`** - Previous approved Status text:
  - From `opportunity.statusText` if exists and approved
  - Default: "No previous status exists." if empty or not approved
- **`{newInput}`** - NEW INPUT text:
  - **For Status approval workflow:** "No new document. The updated status is:\n[approved Status text]"
  - **For NEW INPUT workflow:** The newly uploaded/entered document text

### Expected Output
- A Workplan draft as a **numbered list** (1-5 steps)
- Each step includes:
  - Action (verb-first)
  - Owner: `<<<Us>>>` / `<<<Customer>>>` / `<<<Partner>>>` / `<<<TBD>>>`
  - Target date: `<<<TBD>>>` (ISO date if known, e.g., YYYY-MM-DD)
  - Dependency (optional)
- Sales-process oriented, progressing toward sent quote and signed engagement
- Maintains stability (doesn't rewrite existing steps unless required)
- May include "Quote Inputs Needed" step if commercial details are missing
- Uses placeholders `<<<TBD>>>` where needed
- Matches language of NEW INPUT

### Storage
- Saved to `opportunity.workplanText` in `quoteme.v1.opportunities[]`
- Marked as `hasLmDraft: true` when generated from GT3
- Fully editable by user

## Inference Call C2: Generate/Update Status

### Context
- **Trigger:** Automatically after each NEW INPUT (document/narrative upload) for an Opportunity
- **Location:** `opportunity.html` - NEW INPUT upload handler
- **Function:** `buildStatusNarrative(profile, previousStatus, previousWorkplan, newInput)` in `inference-narratives.js`
- **GT3 Call:** `callGT3(narrative)` in `opportunity.html` line ~444 (parallel with Workplan, atomic commit)

### System Prompt Template
```text
ROLE: Sales Proposal Assistant for global B2B sales.

PROFILE: {profileProse}

PREVIOUS APPROVED STATUS: {previousStatus}

PREVIOUS APPROVED WORKPLAN: {previousWorkplan}

NEW INPUT: {newInput}

OUTPUT REQUIREMENTS:
Output only the updated Status.

Maximize stability:
- Avoid rewriting; append/adjust only what's implied by NEW INPUT.
- Include crisp "where we are now" and "what changed".
- Use placeholders as needed.
- Match language of NEW INPUT.
```

### Dynamic Arguments
- **`{profileProse}`** - Generated by `profileToProse(profile)` (same format as Call A)
- **`{previousStatus}`** - Previous approved Status text:
  - From `opportunity.statusText` if exists and approved
  - Default: "No previous status exists." if empty or not approved
- **`{previousWorkplan}`** - Previous approved Workplan text:
  - From `opportunity.workplanText` if exists and approved
  - Default: "No previous workplan exists." if empty or not approved
- **`{newInput}`** - The newly uploaded/entered document text:
  - Extracted from uploaded file (.txt, .docx) or pasted text
  - Normalized and cleaned (per `text-extraction.js`)

### Expected Output
- A Status draft with **structured sections**:
  - **WHERE WE ARE NOW:** 1-3 bullets (factual)
  - **WHAT CHANGED (from NEW INPUT):** 1-3 bullets
  - **RISKS / BLOCKERS:** bullets (use `<<<TBD>>>` if unclear)
  - **OPEN QUESTIONS:** bullets (use `<<<Ask customer>>>` / `<<<Confirm internally>>>`)
- Concise, factual, progress-oriented
- Maintains stability (preserves prior facts, only appends/adjusts what NEW INPUT implies)
- No fluff, no promises, no invented details
- Uses standardized placeholders
- Matches language of NEW INPUT

### Storage
- Saved to `opportunity.statusText` in `quoteme.v1.opportunities[]`
- Marked as `hasLmDraft: true` when generated from GT3
- Fully editable by user

### Atomic Behavior
- Status and Workplan are generated via **two separate GT3 calls** but treated as **atomic** at the application level
- **Commit rule:** If both calls succeed, update both draft textareas and persist together
- **Failure rule:** If either call fails, show error toast and discard both results (no partial updates)

## Inference Call D: Generate Engagement Proposal (EP)

### Context
- **Trigger:** Automatically when all prerequisites are met:
  - PA exists (PA approval not required per v1.6)
  - Status approved (via glyph toggle)
  - Workplan approved (via glyph toggle)
- **Location:** `opportunity.html` - Auto-generation function `autoGenerateEPIfNeeded()`
- **Function:** `buildEPNarrative(profile, pa, opportunity)` in `inference-narratives.js`
- **GT3 Call:** `callGT3(narrative)` in `opportunity.html` line ~971

### System Prompt Template
```text
ROLE: Sales Proposal Assistant for global B2B sales.

PROFILE: {profileProse}

PROPOSAL ANATOMY (PA): {paText}

OPPORTUNITY TITLE: {title}

APPROVED WORKPLAN: {approvedWorkplan}

APPROVED STATUS: {approvedStatus}

OUTPUT REQUIREMENTS:
- Structured, section-labeled document.
- Section order should follow the PA ordering.
- Each section should be concise, sales-ready, and consistent with approved Workplan/Status.
- Use <<<TBD>>> where necessary.
- Match language of the approved content (and/or Opportunity language context).
```

### Dynamic Arguments
- **`{profileProse}`** - Generated by `profileToProse(profile)` (same format as Call A)
- **`{paText}`** - Proposal Anatomy text:
  - From `currentData.pa.text` if exists
  - Default: "No Proposal Anatomy available." if missing
- **`{title}`** - Opportunity title:
  - From `opportunity.title` if exists
  - Default: "Untitled Opportunity" if empty
- **`{approvedWorkplan}`** - Approved Workplan text:
  - From `opportunity.workplanText` if `workplanApproved === true`
  - Default: "No approved workplan available." if not approved
- **`{approvedStatus}`** - Approved Status text:
  - From `opportunity.statusText` if `statusApproved === true`
  - Default: "No approved status available." if not approved

### Expected Output
- An EP draft with:
  - Clear headings and content blocks
  - **Section order MUST follow the PA ordering** (exact match)
  - Concise, sales-ready, globally usable content
  - **MUST be consistent with APPROVED Workplan/Status**
  - Tables used only when helpful (Pricing, Timeline)
  - Placeholders `<<<TBD>>>` where needed
  - **Explicit "Open Questions" section** if PA includes it
  - **"Quote Validity" and "Currency/Tax Note"** under Commercial Terms (neutral wording)
  - Language matching approved content / opportunity context
  - **HARD RULE:** No invented pricing, dates, SLA, legal clauses, or compliance certifications

### Storage
- Saved to `opportunity.ep.epText` in `quoteme.v1.opportunities[]`
- Marked as `hasLmDraft: true` and `epGeneratedAt: now` when generated
- Displayed directly on Opportunity page using draft-field component
- Fully editable by user (until sent to customer)

## Shared Components

### Profile to Prose Conversion
**Function:** `profileToProse(profile)` in `inference-narratives.js`

**Input:** Profile object with fields:
- `name` (required)
- `roleTitle` (optional)
- `companyName` (required)
- `industrySegment` (required)
- `geography` (required)
- `productServiceCategory` (required)
- `companyDescription` (optional)

**Output Format:**
```
"Name: {name}. Role: {roleTitle}. Company: {companyName}. Industry: {industrySegment}. Geography: {geography}. Product/Service: {productServiceCategory}. Company description: {companyDescription}."
```

**Notes:**
- Only includes fields that have values
- Optional fields are omitted if empty/null
- Returns "No profile available." if profile is null/undefined

## Common Patterns

### Hard Rules (All Prompts)
All prompts enforce these hard rules:
- **Do not invent facts** - If missing, use `<<<TBD>>>` and add to "Open Questions"
- **Do not invent pricing, dates, SLA, legal clauses, or compliance certifications**
- **Use ISO dates (YYYY-MM-DD)** - Avoid relative dates or ambiguous formats
- **Avoid country-specific legal/tax claims** - Prefer internationally neutral wording
- **No slang, hype, or emojis** - Professional, business-appropriate language

### Role Declaration and Operating Principles
All prompts start with:
```
ROLE: Sales Proposal & Quoting Assistant for global B2B.

OPERATING PRINCIPLES:
- Draft-first: write editable drafts; never "lock" decisions.
- Do not invent facts. If missing, use <<<TBD>>> and add to "Open Questions".
- Prefer internationally neutral wording (avoid country-specific legal/tax claims).
- Use ISO dates (YYYY-MM-DD). Avoid slang, hype, emojis.
- Match the language of NEW INPUT (or the dominant language of the opportunity).
```

### Placeholder Usage
All prompts use standardized placeholders consistently:
- `<<<TBD>>>` - Unknown/To be determined
- `<<<Ask customer>>>` - Needs customer confirmation
- `<<<Confirm internally>>>` - Needs internal validation

**Workplan-specific placeholders:**
- `<<<Us>>>` - Owner: Us
- `<<<Customer>>>` - Owner: Customer
- `<<<Partner>>>` - Owner: Partner

### Language Matching
All prompts include language matching requirements:
- Output language must match input language
- If input is English, output is English by default
- For multi-language support, output follows NEW INPUT language

### Stability Rules
For Workplan and Status (C1, C2):
- **Workplan (C1):** Do not rewrite existing steps unless NEW INPUT requires it. Prefer appending new steps or minimally editing specific steps. Add "Quote Inputs Needed" step if commercial details are missing.
- **Status (C2):** Preserve prior facts; only append/adjust what NEW INPUT implies. No fluff, no promises, no invented details.
- Both: Only rewrite when new input requires it

## GT3 Request Format

### Request Body
```json
{
  "narrative": "{full_prompt_string}"
}
```

### Request Headers
- `Content-Type: application/json`
- `X-GT3-Tenant: gt2-quoteme-dev`
- `X-GT3-Data-Track: green`
- `X-GT3-Consent-Version: v1`
- `X-GT3-OpenRouter-Key: {apiKey}` (if provided)
- `X-GT3-OpenAI-Key: {apiKey}` (if provided)

### Response Format
```json
{
  "response": "{generated_text}"
}
```

### Error Handling
- Network errors: Return `{ok: false, error: "Network error: ...", latencyMs: ...}`
- HTTP errors: Return `{ok: false, error: "HTTP {status}: ...", latencyMs: ...}`
- Malformed response: Return `{ok: false, error: "Malformed response: ...", latencyMs: ...}`
